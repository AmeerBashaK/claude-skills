# 02 — UX, Structure & Content

## Process (always in this order)
1. **Discovery**: goal of the site, audience, the one action you want visitors to take, brand keywords (e.g. "refined rustic").
2. **Sitemap**: list the pages and how they nest. Sketch it before anything else.
3. **Wireframes**: grey boxes and placeholder copy for structure only. Don't style them yet.
4. **Visual design**: translate the wireframes, then iterate. The first pass usually looks like "the wireframe painted", which is expected.
5. **Prototype motion**: transitions, scroll moments, hovers.
6. **Build → test → launch → measure.**

## Typical portfolio / studio sitemap
Home → Work (Featured / Case Studies / All, filterable) → Feed or News → About (values, services, team) → Contact.

## Home page anatomy (top to bottom)
| Block | Job |
|---|---|
| Nav | Logo, 4–6 links, one primary CTA |
| **Hero** (above the fold) | Headline that hooks, plus a strong visual. If you lose people here, nothing below matters |
| Quick links / categories | Shortcuts for people who won't scroll |
| Featured work grid | A curated, ordered selection. Add a "View all" link |
| Social proof | Logo quilt, testimonials, numbers. **Only real clients** |
| Approach / value proposition | Why you, told as a story |
| Articles / news | Shows expertise |
| **CTA** | Call, email or book. Make it obvious |
| Newsletter | A value exchange: give something back for the email |
| Footer | Navigation repeated, contact, socials |

## UX rules
- Give people what they want in the **fewest steps**.
- Offer **multiple paths** to the same place (nav, inline links, "view all"). Never make people scroll back up.
- Filters on work pages: people want to see work like the project they have in mind.
- On a one-page scroll, tell the story **one screen at a time**.
- Hover overlays keep grids clean (dim the image, reveal the title), but they need a mobile equivalent.

## Case study template
**Client → Challenge → Solution/Outcome**, then process images, each paired with a short text chunk.
- Break long copy into headline, subhead, callouts, pull quotes and short body chunks. Big unedited blocks of copy are a red flag.
- Pair text with its image so every image has context.
- Have two templates: *case study* (custom, story-led) and *standard project* (an image flow). Systematise the second.

## Copy
- The headline matters more than the image. It should provoke curiosity ("We build bridges"), then the body explains it.
- Sell the **approach**, not just the output. The work is the byproduct of how you think.
- Write the copy before final design where you can. Otherwise design a framework that flexes for longer or shorter text.

## Designer ↔ developer handoff
- Note interactions: hover states, sort order, featured tagging, filters, CMS fields.
- Overlapping type on images and huge background images are hard to build and slow. Flag them early.
- Supply mobile frames for every hover-dependent pattern.
